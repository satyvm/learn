System architecture and trust boundaries

A secure self-service control plane from API request to healthy node.

Control flow

browser → authenticated API → durable operation → worker
worker → Pulumi stack → AWS resources
worker → SSH steps → host configuration
host → Compose → execution + consensus + observability
health evidence → database → API → browser

Sources of truth

ConcernAuthority
User intent and workflow stateApplication database
Cloud resource mappingPulumi state plus typed outputs
Host desired configurationVersioned provisioning specification
Runtime healthSemantic probes and telemetry
Ethereum chain stateExecution and consensus client APIs
Ready means every required boundary has observable evidence. It never means only “the VM exists.”
