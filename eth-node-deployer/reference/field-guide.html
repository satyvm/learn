Ethereum deployer operating field guide

Decision rules for a durable control plane and one safe disposable AWS node.

Lifecycle and identity

deployment (stable user intent + ownership + deterministic stack)
  └─ attempt 1 (leased execution + outputs + ordered evidence)
  └─ attempt 2 (retry; history preserved)

requested → provisioning → configuring → starting → verifying → ready
      active state + verified failure → failed(reason, retry policy)
ready/failed → deleting → deleted(tombstone + cleanup evidence)

AWS mutation gate

  1. Confirm exact account, profile, region, stack, and target deployment.
  2. Verify current price/size, cost ceiling, cleanup time, and expiry tags.
  3. Inspect preview against an expected resource inventory.
  4. Reject world-open SSH, RPC, Engine API, metrics, or admin interfaces.
  5. Confirm state backend, least-privilege roles, and no raw secret persistence.
  6. Reserve enough time to destroy and independently inventory leftovers.
