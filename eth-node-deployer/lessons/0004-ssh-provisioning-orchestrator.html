01 / Mental model

Remote configuration is a state machine

Network reachability, agent readiness, cloud-init, packages, disks, files, and services become ready at different times. Each step needs an observable precondition and postcondition; transport success alone proves little.

Prefer fewer standing credentials

Session Manager can avoid inbound SSH and persistent private keys, but requires instance role, agent, endpoints/connectivity, and IAM policy.

Idempotency starts with a probe

Inspect actual disk, mount, package, file, or service state before applying the smallest necessary change.

Results are structured evidence

Record step name, attempt, timestamps, exit code, verification, and redacted output; never persist full secrets.

02 / Worked example

Specify one step without shell code

STEP CONTRACTprobe → effect → verify
Step: mount node data volume
Precondition: target block device is attached
Probe: current filesystem + mount table + stable device identity
Effect: create filesystem only when absent; mount at chosen path
Postcondition: expected device mounted with expected filesystem
Timeout: bounded per probe/effect/verify
Retry: safe only when probes distinguish completed work
Evidence: command category, exit code, duration, redacted tails
Forbidden: formatting an already initialized unknown device
This contract makes implementation reviewable in any transport. A single shell script returning zero is not the postcondition.
03 / Deliberate practice

Your 60-minute session

  1. 0–15: Read AWS Session Manager overview and setup prerequisites. Compare it with the current project's SSH-key and public-port assumptions in a table: exposure, credentials, logging, prerequisites, file transfer, failure modes.
  2. 15–25: Choose the primary transport for v1 and document the decision plus a fallback. Update your port/IAM design on paper; do not mutate AWS today.
  3. 25–42: Define ordered host steps for boot readiness, data disk, Docker, project/config material, and services. Fully specify only the data-volume step using the contract above.
  4. 42–53: Author the transport-independent step interface and pure result/redaction policy. Test completed, needs-change, terminal-unsafe, timeout, and secret-containing output cases without a remote host.
  5. 53–60: Run checks. Explain which failures are retryable and which require operator intervention. Commit the decision and tested contract.
04 / Retrieval

Close the host notes

Why is command exit code zero insufficient evidence that a remote step succeeded?
Reveal answer

It proves only the command reported success; the intended filesystem, mount, file, service, or health postcondition may still be absent or wrong and requires explicit verification.
