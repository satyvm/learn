By the endCreate a layered verification plan with failure injection and cleanup checks.
01 / Mental model

Build the right picture first

No single test environment proves the whole system. Use fast pure tests for transitions, integration tests for boundaries, preview policy for infrastructure, and a small disposable canary for reality.

Test state transitions

Generate or enumerate legal and illegal transitions, including duplicate events and worker restarts.

Inject boundary failures

Timeout SSH, return partial output, fail a Compose pull, and crash after cloud creation to verify recovery.

Verify cleanup

A passing create test that leaks volumes, IPs, snapshots, or stacks is operationally failing.

02 / Worked example

Test pyramid for systems

ANNOTATED EXAMPLEread → predict → explain
pure: transition + policy + redaction
integration: DB + queue + mocked cloud/SSH
preview: resource and security assertions
canary: disposable AWS host + real clients
recovery: kill worker at every durable boundary
Record cost ceiling, maximum duration, and cleanup evidence for the canary. Treat test infrastructure as production code.
03 / Deliberate practice

Do the work

Predict the result before each step. Keep a small note of what surprised you; surprise is useful evidence that your mental model changed.

  1. Write five invariant tests.
  2. Choose three failure-injection points.
  3. Assert preview contains no world-open admin ports.
  4. Run destroy and inventory leftovers.
  5. Write the operator recovery checklist.
04 / Retrieval

Close the notes

What is the most dangerous untested path?
Reveal answer

A partial failure after resources exist but before state records success, because retries may duplicate resources and cleanup may miss them.
