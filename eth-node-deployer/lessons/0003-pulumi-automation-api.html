Session 03 · AWS safety

Design the first AWS stack

Cloud code begins with a threat model, a cost ceiling, and a destroy story.

By the endAuthor a Pulumi program that previews—not yet creates—the minimal EC2 resource graph with deliberate network, identity, storage, tags, and outputs.
01 / Mental model

Infrastructure is a dependency graph with state

Pulumi compares desired resources to recorded state and provider reality. Names, inputs, outputs, protection, and replacement behavior become lifecycle policy. A preview is a proposal to inspect, not proof of safety.

Start with least exposure

Public P2P needs differ from operator access, RPC, metrics, and Engine API. Build the port matrix before security groups.

Identity belongs to roles

The app worker and EC2 instance need different AWS permissions. Avoid long-lived credentials on the instance.

Tags and outputs are contracts

Ownership, environment, deployment ID, expiry, instance ID, and addresses support recovery, cost inspection, and cleanup.

03 / Deliberate practice

Your 60-minute session

  1. 0–15: Read Pulumi Automation API concepts and AWS security-group guidance. Fill the preflight card and create a port table with source, protocol, purpose, and justification.
  2. 15–27: Derive the minimal resource graph: networking choice, security group, instance role/profile, instance, and persistent storage only if justified. Mark replacement and deletion risk.
  3. 27–47: In a new infrastructure package you name and own, author the Pulumi program and typed inputs/outputs. Use deterministic names and ownership/expiry tags. Do not run an update.
  4. 47–55: Run a preview against a dedicated disposable stack. Read every create/replacement and compare it to your expected inventory. Save a redacted summary.
  5. 55–60: Run checks. Explain why each public rule, IAM permission, output, and protected/retained resource exists. Stop at preview today.
04 / Retrieval

Close the preview

What does a clean Pulumi preview prove, and what does it not prove?
Reveal answer

It shows the planned state diff for the selected stack and program; it does not prove permissions, successful creation, host readiness, node health, cost accuracy, or complete cleanup.
