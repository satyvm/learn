Session 05 · Node runtime

Specify the node runtime

Containers, networks, volumes, and health checks encode operational policy.

By the endDerive and validate a minimal execution/consensus Compose design from client documentation, exposing only justified interfaces.
01 / Mental model

Compose is a dependency and trust graph

An Ethereum node requires execution and consensus clients joined through the authenticated Engine API. Each also joins its own public P2P network. Volumes preserve chain data; health checks report local process/interface facts, not complete sync.

JWT joins clients

Both clients must read the same Engine API secret with restrictive permissions. It must never appear in logs or generated Compose output.

Publish only host interfaces

Containers discover each other by service name. Internal Engine, metrics, and admin interfaces do not need public host bindings.

Startup is not readiness

depends_on and container health sequence startup; Ethereum sync and peer quality need separate probes.

03 / Deliberate practice

Your 60-minute session

  1. 0–15: Read Ethereum node architecture, Docker Compose networking/startup, and the selected execution/consensus client setup pages. Fill the matrix with citations in your project notes.
  2. 15–27: Audit manual-node/eth-testnet/docker-compose.yml: classify every service, port, mount, privileged capability, environment value, version tag, and health signal as required, optional, unsafe, or unexplained.
  3. 27–45: Author a minimal Compose runtime for one client pair in the location your architecture assigns. Pin deliberate versions; define internal networks, persistent volumes, secret mounting, resource expectations, and local health checks.
  4. 45–54: Run docker compose config with safe local values. Inspect the rendered config for published admin ports, accidental secrets, floating tags, and host paths. Start locally only if client requirements make it safe and bounded.
  5. 54–60: Explain what each health check proves and does not prove. Run repository checks and commit the runtime contract.
04 / Retrieval

Close Compose

Which interface connects execution and consensus clients, and why should it not be broadly public?
Reveal answer

The authenticated Engine API coordinates execution payloads between the paired clients; it is an internal control interface whose exposure enlarges a sensitive trust boundary.
