01 / Mental model

Build the right picture first

Fluency appears when you choose commands by structure and recover calmly. Speed is a later side effect; the capstone measures correctness, repeatability, and explanation.

Plan before keys

Search the repository, inspect call sites, identify invariants, and decide which edits are identical versus semantic.

Use an automation ladder

One edit → dot; stable repeated lines → macro; pattern rewrite → substitute; semantic rename → LSP.

Close the loop

Run formatter, typecheck, and tests; navigate failures through location lists; inspect diff; undo or revise.

02 / Worked example

Kata brief

ANNOTATED EXAMPLEread → predict → explain
Open nvim/course.tsx for motion drills.
Then in a sample React project:
1. rename a prop with LSP
2. change repeated JSX attributes with n + .
3. transform fixture rows with a macro
4. run typecheck into quickfix
5. inspect :diff or VCS diff
Narrate each command as operator + target. If an edit fails, explain whether the mistake was range, mode, register, or assumption.
03 / Deliberate practice

Do the work

Predict the result before each step. Keep a small note of what surprised you; surprise is useful evidence that your mental model changed.

  1. Complete three sections of course.tsx.
  2. Perform the five-part refactor.
  3. Save one macro and one search pattern.
  4. Write your personal ten-command retrieval list.
  5. Repeat the kata after two days without notes.
04 / Retrieval

Close the notes

What demonstrates Neovim mastery better than raw keystroke speed?
Reveal answer

Choosing structure-aware, repeatable edits; verifying results; diagnosing behavior; and recovering without losing work.
