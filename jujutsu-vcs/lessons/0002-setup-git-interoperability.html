01 / Mental model

Build the right picture first

Jujutsu commonly uses Git as its storage backend. Git remotes and hosting continue to work, while jj presents a different local workflow. In colocated repos, both tools share the working directory with caveats.

Clone explicitly through Git

jj git clone creates a jj repository backed by Git. Existing repos can be initialized with an appropriate colocated workflow after reading current docs.

Identity is required

Configure user.name and user.email before creating shareable work. Verify repo and user-level configuration sources.

Remote bookmarks are distinct

main@origin is the remote-tracking view; local main is a bookmark you deliberately move and export.

02 / Worked example

Safe setup

ANNOTATED EXAMPLEread → predict → explain
jj git clone <url> atlas
cd atlas
jj config set --user user.name "Your Name"
jj config set --user user.email "you@example.com"
jj log
jj bookmark list --all
Use a disposable fork for the course. Do not switch between Git and jj commands blindly until you understand when colocated state imports or exports.

  2. Inspect config and operation log.
  3. List local and remote bookmarks.

04 / Retrieval

Close the notes

Is a jj bookmark exactly a Git branch?
Reveal answer

It maps to a Git ref for interoperability, but jj does not require each change to be attached to a bookmark during local work.
