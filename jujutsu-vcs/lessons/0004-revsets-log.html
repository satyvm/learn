01 / Mental model

Build the right picture first

Commands accept revision expressions instead of only branch names or hashes. Revsets compose sets and graph relationships, making history queries precise and reusable.

Symbols are graph-relative

@ is working copy, @- its parent, root() the virtual root, and trunk() the configured mainline.

Ranges differ

x..y selects ancestors of y excluding ancestors of x; x::y selects commits on DAG paths from x to y.

Functions express meaning

bookmarks(), author(), description(), mine(), conflicts(), and mutable() can build focused work views.

02 / Worked example

Useful queries

ANNOTATED EXAMPLEread → predict → explain
jj log -r 'trunk()..@'
jj log -r 'mine() & mutable()'
jj log -r 'conflicts()'
jj log -r 'trunk()::@'
jj diff -r '@-'
Quote expressions so the shell does not interpret operators. Start with log to inspect a set before passing it to a rewriting command.
03 / Deliberate practice

Do the work

Predict the result before each step. Keep a small note of what surprised you; surprise is useful evidence that your mental model changed.

  1. Predict each query’s set on paper.
  2. Run it and compare the graph.
  3. Create an alias for your open stack.
  4. Use the same revset with show or diff.
04 / Retrieval

Close the notes

Why inspect a revset with jj log before rewriting?
Reveal answer

A revset can select multiple or unexpected revisions; visual confirmation reduces the risk of applying a graph mutation to the wrong set.
