TypeScript build-session field guide

A repeatable protocol for learning by authoring the real node control plane.

The 60-minute loop

TimeMoveEvidence
0–10Retrieve yesterday's model; predict today's boundary.Written prediction before files/docs.
10–20Read only the official sections needed for the decision.Terms, constraints, and source link.
20–45Author the smallest coherent change yourself.Diff you can explain line by line.
45–55Run a tight test/check; break one case deliberately.Expected failure, then passing feedback.
55–60Explain and commit, or record the precise blocker.One-sentence model plus clean check.

Error and stuck protocol

  1. Copy the exact command and first actionable diagnostic.
  2. Name the operation TypeScript or the runtime was checking.
  3. Reduce the problem to the owning file/package and smallest input.
  4. Inspect the receiving declaration or official page before editing.
  5. State one hypothesis; make one change; rerun the narrowest feedback.
  6. After 15 focused minutes, ask the teaching agent to question the hypothesis or inspect the attempt—not to supply a finished feature.

Boundary ladder

unknown input → Zod parse → domain command → authenticated actor
→ authorized operation → database constraints → public tRPC result
→ TanStack server state → exhaustive interface states
