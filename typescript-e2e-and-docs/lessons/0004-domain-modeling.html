Session 04 · Foundations

Read generic relationships

Angle brackets connect positions; they do not manufacture runtime truth.

By the endExplain how Context and AppRouter types flow through the existing stack and author one useful generic relationship.
01 / Mental model

Find every occurrence

A type parameter is a placeholder connecting two or more positions: input to output, key to object, router to client. Read a generic by circling each occurrence and stating the promise between them.

Inputs create evidence

Inference commonly starts from function arguments or a concrete type supplied to a library factory.

Constraints grant operations

A constraint limits possible types so an implementation may safely use particular properties.

Types disappear at runtime

A generic result still needs parsing when its data originates outside the program.

03 / Deliberate practice

Your 60-minute session

  1. 0–15: Read the Handbook generics introduction. For its identity example, state what remains the same between parameter and return.
  2. 15–30: Trace the two relationships above in the actual repository. Hover intermediate values and write the inferred type at each arrow. Follow definitions until you can state the library promise.
  3. 30–45: Author a small generic lookup for values keyed by deployment ID, or another relationship your domain genuinely needs. First write the promise in English; then choose type parameters. Avoid a type parameter used only once.
  4. 45–53: Add calls that prove preservation of a specific deployment shape and rejection of an incompatible shape. Use type-checking as the feedback loop.
  5. 53–60: Run checks. Explain why parse<T>(text): T would be an unsupported promise. Stop when you can trace AppRouter without notes.
04 / Retrieval

Close the declarations

Why is a generic return type suspicious when the type parameter appears nowhere in the input?
Reveal answer

The implementation receives no evidence for the caller-selected type, so it can promise a shape the runtime value has never proven.
