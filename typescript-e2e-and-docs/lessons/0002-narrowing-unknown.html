Use the compiler as a conversation

Write a small domain function, then let errors expose assumptions.

By the endAuthor a typed deployment-summary function and reduce every compiler diagnostic to one plain-language mismatch.
01 / Mental model

Types describe permitted operations

TypeScript checks whether the value you have supports the operation you attempt. A long error is usually a path: assignment → property → callback → parameter. Your job is to find the first false assumption, not silence the message.

Infer locally

Let literals and obvious return values infer. Add annotations where a boundary or promise must be visible.

Read outside-in

First name the operation being checked; then follow nested “not assignable” clauses to the deepest concrete mismatch.

Never erase evidence

any, broad assertions, and ignoring diagnostics make the conversation stop before the bug is understood.

02 / Worked example

Translate a requirement before coding

DESIGN PROMPTnoun → data · verb → function
Requirement:
“Show a short label for a requested node containing
its network, AWS region, and chosen client pair.”

Questions to answer yourself:
• Which values are finite choices?
• Which values remain arbitrary strings?
• What exact input does the formatter need?
• What exact output does it promise?
Do not search for a finished model. Use the requirement to draft one, then ask the compiler what your calling code contradicts.
03 / Deliberate practice

Your 60-minute session

  1. 0–12: Read the Handbook sections “Everyday Types,” “Functions,” and “Object Types.” In notes, define parameter, return type, property, literal union, and optional property in your own words.
  2. 12–30: Choose an appropriate domain location under packages/api/src. Author a deployment-draft type and a pure summary function from the requirement. Do not use any or as.
  3. 30–42: Call it once correctly and three times incorrectly: missing field, wrong primitive, unsupported finite choice. Run the type check after each and translate the first diagnostic into “I supplied ___ where ___ was required.”
  4. 42–52: Remove the intentionally invalid calls. Add a small runtime test for a valid label using the repository's chosen test runner; read its official getting-started page first.
  5. 52–60: Run the targeted test and bun run check. Commit only when both pass. Explain why each annotation exists and what inference handled for you.
04 / Retrieval

Close the editor

A call says an argument is not assignable because its network property is a general string. What is the first mismatch?
Reveal answer

The caller possesses string, while the function requires one of a finite set of network literals. Investigate where the caller's value originates instead of asserting it narrower.
