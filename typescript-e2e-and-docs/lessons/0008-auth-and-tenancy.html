01 / Mental model

Authorization belongs beside data access

Authentication establishes an actor. Authorization evaluates an operation on a specific resource. UI guards improve experience, but only server-side policy and scoped queries defend the boundary.

Context is request-scoped

The current Hono request provides headers; Better Auth resolves a session; tRPC middleware narrows the context for protected procedures.

Ownership is a predicate

Looking up by deployment ID and checking afterward can leak existence or invite mistakes. Include actor ownership in the query condition.

Roles do not replace ownership

Approval/admin policy and tenant access are separate decisions with separate tests and audit requirements.

03 / Deliberate practice

Your 60-minute session

  1. 0–15: Read Better Auth installation, session, and database additional-field sections. Trace the exact existing files in the diagram and write the type of ctx.session before and after middleware.
  2. 15–27: Write an access matrix for list, view, create, retry, destroy, and approve across the four test identities. Mark unanswered product decisions.
  3. 27–43: Author one tenant-scoped repository/query function for viewing a deployment. Make the actor ID an unavoidable input. Decide how “missing” and “belongs to someone else” appear externally.
  4. 43–53: Test owner success, other-user denial, and missing deployment. Ensure the failing case does not reveal another tenant's data or secret fields.
  5. 53–60: Run tests and checks. Explain authentication, approval, role, and ownership as four distinct facts.
04 / Retrieval

Close the auth files

Why is checking ownership after a lookup by deployment ID weaker than scoping the lookup itself?
Reveal answer

The unscoped lookup retrieves another tenant's row and relies on every caller to remember a later check; a scoped predicate makes unauthorized data absent at the query boundary.
