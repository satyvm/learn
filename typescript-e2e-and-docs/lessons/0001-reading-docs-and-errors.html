01 / Mental model

A repository is a graph

Folders are ownership boundaries; imports are edges; commands execute parts of the graph. Do not try to understand every file. Follow one value from the place it is displayed backward to the place it is produced.

Apps run

apps/web renders the browser and apps/server accepts HTTP. Begin at observable behavior.

Packages define boundaries

packages/api, auth, db, env, and ui are imported capabilities, not miscellaneous folders.

Tools give feedback

The dev server shows runtime behavior; bun run check shows static and formatting failures. Both are evidence.

03 / Deliberate practice

Your 60-minute session

  1. 0–10: From the project root, read package.json and Bun's workspace page. Predict what bun run dev and bun run check execute. Run the check and save its exact result.
  2. 10–25: Start the app. Without global searching first, follow the health value backward through the four files above. Draw the import/request path in your own notes.
  3. 25–45: Change only the health procedure's returned value, predict the browser result, and observe it. Restore or improve the value deliberately; do not leave a mystery edit.
  4. 45–55: Run bun run check. If it fails, read the first actionable diagnostic, locate the owning package, and fix only that cause.
  5. 55–60: Write: “The browser knows the server result because …” Name every boundary. Stop when the check passes and you can explain the trace without reopening files.
04 / Retrieval

Close the repository

Which file defines the health behavior, and which file merely consumes its inferred contract?
Reveal answer

packages/api/src/routers/index.ts defines the procedure; apps/web/src/routes/index.tsx consumes it through the typed client created in apps/web/src/utils/trpc.ts.
