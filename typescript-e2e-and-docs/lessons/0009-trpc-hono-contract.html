01 / Mental model

A procedure is an adapter

The procedure accepts transport input, invokes parsing and policy, calls persistence, maps known failures, and returns a deliberate public shape. Long-lived deployment work must not begin inside this request yet.

Input is executable

Attach the Session 6 schema so the procedure receives parsed data, not a declared fiction.

Context supplies identity

Use the protected procedure and pass the actor explicitly into domain/data functions.

Return public data

Do not leak raw rows, credentials, internal failure details, or provider state merely because inference makes it easy.

02 / Worked example

Write the contract ladder

REQUEST PATHboundary → boundary
HTTP request
  ↓ Hono middleware and mounted tRPC adapter
  ↓ tRPC procedure + parsed input
  ↓ authenticated, authorized actor
  ↓ domain decision
  ↓ tenant-scoped database operation
  ↓ public result or mapped error
  ↓ inferred client contract

Every arrow needs one testable promise.
If the procedure contains database schema design, cloud provisioning, UI state, and retry loops, the boundaries have collapsed. Keep today's operation local and fast.
03 / Deliberate practice

Your 60-minute session

  1. 0–15: Read tRPC procedures, context, and Hono testing. Inspect how the existing privateData procedure and server adapter work; list what is framework behavior versus application policy.
  2. 15–25: Define one operation's input, authorization rule, database effect, public output, and named failures. Choose either create-draft or list-owned-deployments—whichever your schema can honestly support.
  3. 25–43: Author the procedure by composing existing parser, session policy, and query. Keep it thin. Do not start Pulumi, SSH, or Compose.
  4. 43–53: Test invalid input, unauthenticated request, authorized success, and absence of secret/internal fields. Use the narrowest practical boundary; add an Hono request test if your app export permits it.
  5. 53–60: Run tests and checks. Trace the inferred output into apps/web with editor hovers, without adding UI yet.
04 / Retrieval

Close the router

Why should a create request record intent and return quickly instead of provisioning an EC2 instance inline?
Reveal answer

Cloud work can exceed request lifetimes and fail partially; durable intent lets a separate worker retry, resume, and report progress independently of the HTTP connection.
