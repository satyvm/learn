Model deployment states

A union can encode the lifecycle before cloud side effects exist.

By the endReplace flag-shaped thinking with a discriminated deployment state and an exhaustively checked transition function.
01 / Mental model

Each state owns exactly its data

Flags permit contradictions. A discriminated union names mutually exclusive situations and attaches only the evidence available in each. A transition function becomes the policy boundary.

States are facts

requested, provisioning, ready, and failed should describe observed workflow facts.

Events request change

An event does not guarantee its transition is legal; the transition function must decide.

Exhaustiveness protects growth

A never check makes a newly added state fail every incomplete decision point.

02 / Worked example

Design the table first

POLICY TABLEcurrent + event → next
requested    + worker_claimed       → provisioning
provisioning + infrastructure_ready → configuring
configuring  + node_healthy         → ready
any active   + step_failed          → failed
failed       + retry_requested      → ?
ready        + retry_requested      → illegal

For every “?” decide:
• what evidence is required?
• what attempt history is preserved?
• who is allowed to request it?
The table is not an implementation. It exposes unanswered policy questions before code distributes them across UI, API, database, and workers.
03 / Deliberate practice

Your 60-minute session

  1. 0–12: Read Handbook union narrowing and never exhaustiveness. List the contradictory combinations possible in the current database's free-text status plus nullable infrastructure fields.
  2. 12–25: Draft your complete state/event table on paper. Include requested, active stages, ready, failed, and deleting/deleted. Mark illegal transitions explicitly.
  3. 25–43: Author domain state and event unions plus a pure transition function. Choose whether illegal transitions return data or throw; justify the choice for callers and tests.
  4. 43–53: Test at least four legal and four illegal transitions, including duplicate delivery of one event. Add the exhaustive check.
  5. 53–60: Run tests and checks. Explain which state owns instanceId, which owns a failure reason, and why. Do not change the database yet.
04 / Retrieval

Close the state table

What bug does an exhaustive never check turn into a compiler error?
Reveal answer

Adding a new union member without handling it in an existing switch or decision function; the formerly unreachable value can no longer be assigned to never.
