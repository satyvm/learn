01 / Mental model

Build the right picture first

Parsing is a phase change: unknown external representation becomes either structured errors or trusted internal data. Keep coercion and defaults at this edge.

Parse, do not merely check

A good boundary may trim text, normalize dates, reject excess, and return a value shaped for the next layer.

Separate transport from domain

HTTP strings and database rows are representations. Map them to domain concepts instead of exporting storage shapes everywhere.

Errors need paths

Structured issues let clients attach feedback to fields and let logs aggregate failure categories.

02 / Worked example

Schema-first input

ANNOTATED EXAMPLEread → predict → explain
const CreateProject = z.object({
  name: z.string().trim().min(3).max(80),
  visibility: z.enum(["private", "team"]),
}).strict();
type CreateProject = z.infer<typeof CreateProject>;
The same declaration executes at runtime and supplies a static type. strict prevents silently accepting misspelled fields.
03 / Deliberate practice

Do the work

  1. Write the raw boundary as unknown.
  2. Define normalization and constraints.
  3. Parse with success and failure examples.
  4. Map issues into stable client error codes.
