Reference Guide

Stack Architecture Reference

An overview of the modern full-stack TypeScript monorepo and its core design decisions.

Why This Tech Stack?

This tech stack is carefully curated to offer the best developer experience, build speed, and runtime performance while maintaining end-to-end type safety.

  • Turborepo: A high-performance build system for JavaScript and TypeScript monorepos. It orchestrates task execution, caches build artifacts, and ensures that you only rebuild what changed.
  • TypeScript & tRPC: Provides end-to-end type safety. Instead of writing REST API schemas manually, tRPC allows the frontend clients to import types directly from the backend API server. If you rename a database field or a function, your build will fail immediately at compile time.
  • Bun: A incredibly fast JavaScript runtime that replaces Node.js, npm, and yarn. It speeds up dependency installation, test execution, and local development start times.
  • Hono: A lightweight, fast, and edge-ready web framework. Hono acts as our router for standard HTTP endpoints and hosts the tRPC API endpoints.
  • Drizzle ORM & PostgreSQL: A TypeScript-first ORM. Unlike bulky ORMs, Drizzle allows you to write type-safe SQL queries with zero overhead, and automatically generates migration files based on your TS schemas.
  • Better-Auth: A modern, drop-in authentication library built with developer experience and type safety in mind. It handles sessions, credentials, and OAuth out of the box.
  • TanStack Router: A fully type-safe, file-based router for React. It guarantees that routing links, query parameters, and loader states are validated at compile time.
  • React Native & Expo: Allows you to build truly native Android and iOS mobile applications using React, sharing code and configuration with the web application seamlessly.
  • Tauri: Used to build native desktop applications using lightweight webviews, featuring a fast and secure Rust backend.
  • Tailwind CSS & shadcn/ui: Rapidly build modern interfaces using utility classes and accessible, fully customizable, copy-pasteable UI components.
  • Biome & Husky: Biome replaces ESLint and Prettier, linting and formatting code in milliseconds. Husky runs these tools as pre-commit hooks to ensure clean code gets into Git.

Missing Pieces to Consider

While the stack is incredibly robust, you will eventually need to decide on options for deployment, global state management, and CI/CD:

  • Hosting: Deploy the frontend web app on Vercel or Cloudflare Pages. Host the Hono API server on Railway, Fly.io, or AWS. Build and distribute the mobile app using EAS (Expo Application Services).
  • State Management: Use Zustand or Jotai if you need complex client-side state outside of server cache. For server state, tRPC has TanStack Query built-in.
  • CI/CD: Set up GitHub Actions to run Biome checks, lint your code, execute test suites, and run Turborepo builds on every Pull Request.

Project Structure Mapping

A typical monorepo structure divides responsibilities between frontend applications (in apps/) and shared packages (in packages/):

project-x/
├── apps/
│   ├── web/     -> The browser application (React + TanStack Router).
│   ├── native/  -> The mobile application (React Native + Expo).
│   └── server/  -> The backend API server (Hono + tRPC router).
├── packages/
│   ├── api/     -> The business logic and tRPC routers (shared by Web and Mobile).
│   ├── auth/    -> Authentication configuration, adapters, and setup.
│   └── db/      -> The database connection, schemas, and migrations.

Feature Development Workflow

When developing a new feature (e.g., adding a "User Comments" feature), follow this sequential process:

  1. Database (packages/db): Define the database tables in Drizzle, generate a migration, and run db:push to apply it.
  2. API (packages/api): Add a new tRPC route (query or mutation) that imports the DB schema and handles the business logic.
  3. Server (apps/server): Ensure the route is registered on the main API router (usually automatic if importing directories).
  4. UI Clients (apps/web & apps/native): Fetch the data using the type-safe tRPC client (e.g., trpc.comments.get.useQuery()) and render the components using Tailwind and shadcn/ui.
