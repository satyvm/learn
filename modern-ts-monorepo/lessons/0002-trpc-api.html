Lesson 2

tRPC & The API Layer

Bypass REST boilerplate and share types directly between frontend and backend.

Correct! You start at the database layer (packages/db) because data constraints and schemas govern the application structure.

Why do we use tRPC?

Traditionally, developers write REST APIs with endpoints and document them using tools like OpenAPI (Swagger). The client fetches data and parses it without compile-time guarantees of the shape. If you change a database schema field, the client has no idea until it runs and breaks.

tRPC (TypeScript Remote Procedure Call) eliminates this. By exporting the TypeScript AppRouter type definition from your backend, your React web app and Expo mobile app can call backend functions directly with full compiler-level validation. If you change or rename an API query on the backend, the compiler will instantly throw errors on the frontend.

How it works under the hood

  1. Define Procedure (Server): You write an API route, e.g., getUser: publicProcedure.query(() => db.query.users.findMany()).
  2. Export Types: The backend exports the types of the router, but no actual runtime code.
  3. Invoke Procedure (Client): The React app imports the types and uses a hook like trpc.getUser.useQuery().
