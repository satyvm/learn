01 / Mental model

Build the right picture first

A first run is a diagnostic protocol. Validate the cheapest assumptions first, then move outward: toolchain → dependency graph → builds → processes → browser behavior.

Read before running

Inspect package scripts and environment examples. A command copied from memory may bypass the repository’s intended workflow.

One failure at a time

Run typecheck or one app before every service. Smaller feedback surfaces produce better error hypotheses.

Record expected signals

A port opening is not the same as a healthy app. Define a health response, visible route, and known log line.

02 / Worked example

Layered protocol

ANNOTATED EXAMPLEread → predict → explain
pnpm install --frozen-lockfile
pnpm turbo run typecheck --dry
pnpm check
pnpm dev
The dry run reveals task selection and dependency order before work executes. The check stage separates static failures from process orchestration.
03 / Deliberate practice

Do the work

Predict the result before each step. Keep a small note of what surprised you; surprise is useful evidence that your mental model changed.

  1. Predict which tasks will run for one changed package.
  2. Run the graph or dry-run command and compare.
  3. Record one expected HTTP and one UI signal.
04 / Retrieval

Close the notes

Why run a task-graph dry run?
Reveal answer

It tests your mental model of package relationships and catches missing or unexpectedly broad task dependencies cheaply.
