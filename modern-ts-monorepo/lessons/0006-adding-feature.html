01 / Mental model

Build the right picture first

A vertical slice is a thin, end-to-end behavior. It is the fastest way to test whether architecture helps real work: schema, query, procedure, client state, and tests all move together.

Start with invariants

Write facts that must remain true: comments belong to posts, authors may edit their own comments, and empty bodies are invalid.

Schema is not the whole model

Database constraints preserve structural truth; application authorization preserves actor-specific policy.

Errors are product states

Not found, forbidden, invalid, and temporarily unavailable require different client behavior.

02 / Worked example

Move in dependency order and keep the slice runnable. Avoid designing an all-purpose abstraction before the second real use case exists.
03 / Deliberate practice

Do the work

Predict the result before each step. Keep a small note of what surprised you; surprise is useful evidence that your mental model changed.

  1. Write three invariants for a small feature.
  2. Implement the smallest database change and procedure.
  3. Render success, empty, forbidden, and failure states.
  4. Add one server boundary test and one UI behavior test.
04 / Retrieval

Close the notes

Which should be shared: a database row type or the procedure output?
Reveal answer

Usually the procedure output. It is the public contract; exposing raw persistence shapes couples clients to storage decisions.
