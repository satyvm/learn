Feature Development End-to-End

Implement a new feature across the entire monorepo stack step by step.

Correct! Turborepo (or simply turbo) manages the build pipelines and development scripts, executing them concurrently across your package workspaces.

E2E Feature: Adding Post Comments

To master code progression in the monorepo, let's trace how we would build a "Comments" module under a post.

Step 1: Write Database Table (packages/db)

Open packages/db/src/schema.ts and define the schema for comments using Drizzle ORM:

// schema.ts
export const comments = pgTable("comment", {
  id: serial("id").primaryKey(),
  postId: integer("post_id").notNull(),
  content: text("content").notNull(),
});

Run Drizzle migrations to sync your schema with your local PostgreSQL instance.

Step 2: Define tRPC Procedure (packages/api)

In packages/api/src/router/post.ts, write a new mutation to add comments:

// router/post.ts
addComment: publicProcedure
  .input(z.object({ postId: z.number(), content: z.string() }))
  .mutation(async ({ ctx, input }) => {
    return ctx.db.insert(comments).values(input);
  })

Step 3: Render in React Web View (apps/web)

In your frontend React component, fetch the mutation helper and wire it to a button:

// PostView.tsx
const mutation = trpc.post.addComment.useMutation();

<Button onClick={() => mutation.mutate({ postId: 1, content: "Great post!" })}>
  Comment
</Button>

Why this workflow rules

Observe the developer experience: because everything is written in TypeScript, the moment you call mutation.mutate() in apps/web, your IDE will validate the parameters based on the Zod schema you wrote in packages/api. Changing a parameter name in the router will instantly trigger a compilation error in the React file.
