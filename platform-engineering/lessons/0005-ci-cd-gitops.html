Delivery, GitOps, and progressive change

Separate artifact creation from environment reconciliation.

By the endDesign a pipeline where one immutable artifact is promoted with policy and rollback.
01 / Mental model

Build the right picture first

Continuous integration proves a change and produces an immutable artifact. Delivery changes declared environment intent. A GitOps reconciler continuously compares that intent with the cluster.

Build once, promote many

Use the same digest through environments. Rebuilding introduces unreviewed variation.

Git records intent, not health

A merged manifest is auditable desired state. Reconciliation and runtime signals still determine whether rollout succeeded.

Rollback is another change

Prefer forward fixes when data compatibility demands it. Practice both rollback and roll-forward before incidents.

03 / Deliberate practice

Do the work

Predict the result before each step. Keep a small note of what surprised you; surprise is useful evidence that your mental model changed.

  1. Draw build and deploy as separate stages.
  2. Pin an image digest.
  3. Define canary success and abort signals.
  4. Simulate a revert and record convergence.
04 / Retrieval

What does GitOps add beyond CI/CD?
Reveal answer

A continuously reconciled, versioned declaration of environment intent, with drift detection and auditable changes.
