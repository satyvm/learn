01 / Mental model

Build the right picture first

A platform makes expensive, privileged actions easy, so it must also make provenance, budgets, quotas, backups, and recovery visible. Guardrails belong in the self-service contract.

Provenance supports verification

Link source, builder identity, dependencies, artifact digest, signature, and deployment. Verification should happen before privileged execution.

Cost has an owner

Tags, budgets, quotas, expiry, and showback help teams connect requests to consequences without ticket gates.

Recovery needs rehearsal

Backups without restore tests are hypotheses. Define RTO/RPO, dependencies, degraded modes, and game days.

02 / Worked example

Three-axis review

ANNOTATED EXAMPLEread → predict → explain
Change: create preview environment
Trust: verified image + approved module
Cost: quota + TTL + owner label
Resilience: regional dependency + cleanup retry + state backup
Evaluate capabilities across all three axes during design review; retrofitting them after adoption creates painful migrations.
03 / Deliberate practice

Do the work

Predict the result before each step. Keep a small note of what surprised you; surprise is useful evidence that your mental model changed.

  1. Draw the source-to-runtime trust chain.
  2. Add quota and automatic expiry to a capability.
  3. Choose RTO/RPO for platform state.
  4. Run a tabletop loss-of-control-plane scenario.

What makes a backup trustworthy?
Reveal answer
